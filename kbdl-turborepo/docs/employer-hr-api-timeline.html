Employer HR Backend Delivery Plan

Audience: Manager / stakeholders
Scope: KBDL Employer — Employees, Attendance / OT, Payroll, Leave
Context: UI already exists (mostly static/mock). Backend must deliver data models, business rules, secure APIs, and FE contracts.

Estimate

Why “just APIs” is misleading

For every screen, backend work includes:

  1. Domain / DB design — new tables or extensions aligned to Company / CompanyMember / Department / roles
  2. Authorization — every call scoped to employer company_id; role checks (OWNER/ADMIN/HR/FINANCE)
  3. Validation & contracts — Zod/OpenAPI request-response; FE contract freeze meetings
  4. Business rules — status machines; payroll stage locks; leave balance math
  5. Transactions & consistency — onboard atomic writes; no double-disburse
  6. Integrations — file storage for documents/payslips; optional notify on send
  7. Seed + migration — demo data matching UI for FE integration
  8. Testing & docs — edge cases; Swagger; Postman; FE handoff

Phase A Week 1 (5 days): Employee directory + onboarding

Goal: Replace employee list mock + make “Add New Onboard” production-capable.

Day-by-day backend work

Day Work package (not just “one API”)
D1 Map UI list columns → DB (User, CompanyMember, EmployeeEmployment, ratings). Design list DTO. Company-scoped query plan + indexes. Auth middleware path for employer.
D2 Implement GET .../employees with search, multi designation, multi status, pagination, sort. Empty/error states. Tests for filters.
D3 Meta APIs for dropdowns: designations, departments, branches, supervisors, work_shifts (HR templates — not marketplace shifts). Align with CompanyRole / Department catalogs.
D4 Expand onboard domain: draft vs submit; field mapping for personal + job + payment + identity + salary; unique employee_no / phone; status Onboard / Probation.
D5 Transactional POST .../onboard. OpenAPI + seed 20–50 employees. FE contract review.

APIs delivered

  • GET /api/v1/operations/employer/employees
  • GET /api/v1/operations/employer/meta/designations|departments|branches|supervisors|shifts
  • POST /api/v1/operations/employer/onboard (full body, draft/submit)

Exit criteria

  • List + filters work against real DB
  • Onboard form creates a real employee end-to-end
  • Swagger + Postman handed to FE

Phase C · Heaviest 10 working days: Payroll core

Goal: Power Run Payroll (4 stages), Worker Wages, Payslips.
Why 10 days: This is a workflow + calculation product, not a CRUD list.

What must be built under the hood

Layer Concrete work
Schema payroll_runs, run employees, attendance snapshots (from attendances), wage/deduction lines, disbursements, wage masters, payslips — reuse company_work_schedules / overtime_settings / work_shifts
State machine Stages attendance → wages → deductions → disburse with lock after confirm
Calculation engine Present/leave/absent/OT → payable days → basic + OT + allowances → gross → EPF/ESIC/TDS/LWF/advance → net
Config Pay-cycle + statutory % + work schedule (which days off) + OT rules (threshold, multiplier, holiday/weekoff OT)
Idempotency Disburse once; safe payslip regenerate; prevent double submit
Money safety Decimal precision, rounding, audit (who confirmed which stage)
Auth FINANCE/OWNER/ADMIN for disburse; HR for attendance edits

Day-by-day (10 days)

Day Work package
D1 Domain workshop + ERD. Map every UI column on 4 Run steps. Period key, statuses.
D2 Migrations + indexes. Seed wage masters. Repository layer.
D3 POST/GET payroll/runs — create month run; pull baseline from attendances (present / OT / absent / week_off); summary stats.
D4 Attendance stage APIs + confirm (locks stage). OT pay uses overtime_settings.rate_multiplier + worked hours vs shift / schedule.
D5 Wage calculation service + confirm; recalc after edits.
D6 Deduction engine (EPF/ESIC/TDS/LWF/advance) + custom add + confirm.
D7 Disburse NEFT/UPI/Cash; draft vs confirm; rollback cases.
D8 Worker Wages master list/filter/patch.
D9 Payslips generate/list/download/send.
D10 OpenAPI, Postman, integration tests (happy path + double-disburse guard), FE walkthrough, bugfix.

Exit criteria

  • Full month path: Attendance → Wages → Deductions → Disburse against API
  • Net pay matches engine rules for seeded workers
  • Payslips after disburse; Swagger complete for payroll core

Payroll & Attendance data model (agreed)

UI settings: /payroll/settings — separate table per domain, one row per company_id where noted. Aggregate API GET/PUT .../payroll/settings (transaction).

Reuse companies for name/GST/address + compliance (pan, state, epf_registration_no, esic_code).

Effort unchanged: attendance APIs land in Phase B (profile tab) + Phase C (payroll stage); settings/schedule/OT GET-PUT in Phase D — still within the same 5-week calendar.

Settings (1 row / company)

Table Purpose / key fields
payroll_settings pay_frequency, pay_day, payroll_cutoff_day, financial_year_start, lock_after_processing
statutory_settings employee/employer PF & ESIC rates, professional_tax, labour_welfare_fund
payment_settings default_disbursement_method, allow_bank_transfer, allow_upi, allow_cash
company_work_schedules mon–sun working flags, daily_work_hours, weekly_work_hours, half_day_percentage, absent_deduction_type
overtime_settings enabled, ot_after_hours_per_day/week, rate_multiplier, max_ot_hours_per_day, include_holiday_ot, include_weekoff_ot, approval_required, auto_calculate_ot

Attendance & HR shifts (operational)

Table Purpose / key fields
work_shifts HR templates (General / Morning / Evening / Night): name, start_time, end_time, break_minutes — not marketplace shifts
employee_shifts company_member_id → work_shift_id, effective_from / effective_to
attendances company_member_id + date (unique): check_in, check_out, worked_minutes, ot_minutes, status (present/absent/half_day/leave/holiday/week_off), source, marked_by
company_holidays date, name, is_optional — drives holiday OT + attendance status

OT example: shift 09:00–18:00 (8h after break), check-out 21:00 → 3h OT × hourly × rate_multiplier. Week-off work uses schedule + include_weekoff_ot.

On company create (or first GET settings): seed defaults for settings tables + standard work_shifts. Seed already includes sample attendances for demo.

One-slide summary for manager

Problem: Employer Employees / Payroll / Leave UIs are built on static data. Backend must deliver a real HR + payroll system behind them.

Effort:

  • Employees list + onboard: 1 week
  • Employee profile: 1 week
  • Payroll core: 10 working days (workflow + wage/deduction engine + disburse + payslips — not “a few APIs”)
  • Leave + settings + hardening: 1 week

Total: ~5 weeks with weekly demos.
FE integrates in parallel once Week 1 contracts ship.

Success: Employer can onboard employees, mark/view attendance & OT, run a full monthly payroll, issue payslips, and process leave — all against production-shaped APIs documented in Swagger.
